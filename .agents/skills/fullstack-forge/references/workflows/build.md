# Build workflow

Load this reference for a substantial feature that needs durable framing, planning, resumption, or
tiered evidence. Do not initialize Build state for a small wording, styling, or isolated correction.

1. Frame the intended outcome, users, durable business rules, sensitive boundaries, constraints, and
   explicit non-goals.
2. Discover the existing project and derive a safe feature identifier rather than asking the user to
   invent internal vocabulary.
3. Record applicability and a proportional plan under `.forge/build/`.
4. Implement through existing architecture, preserve decisions, and produce evidence while building.
5. Re-derive applicability at `check` and `done`; accept positive results only from exact registered
   producers whose evidence envelope matches the root, revision, inputs, artifacts, and expiry.

Build state never satisfies Audit or Ship gates. Legacy state is changed only through the explicit,
journaled migration command.
