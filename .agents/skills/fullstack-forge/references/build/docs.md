# Build brief: Documentation

## Decide before coding

- Decide which existing documentation (README, API reference, runbook) this feature will require updating before it ships stale.
- Decide the setup or configuration step a new contributor or operator needs to use this feature, and confirm it does not exist only in chat or memory.
- Decide whether this feature changes a documented command, endpoint, or diagram, and treat that update as part of the feature, not a follow-up.
- Decide what limitation or manual step this feature has that must be stated plainly rather than implied.
- Decide any example or sample value used in documentation for this feature is free of real secrets or personal data.

## Evidence to produce while building

- The specific documentation files updated alongside this feature, matched to what actually changed.
- A followed quick-start or setup step from a clean context, confirming it still works after this change.
- Confirmation that any new or changed command, endpoint, or diagram in the docs matches current code.
- Confirmation that documentation examples contain no real secrets or personal data.
