# Visual direction

Owner: `forge-ui`. Product needs constrain this concern; aesthetics never override usability or
accessibility.

## Load when

- Creating a substantial screen, public page, product surface, or redesign.
- The request changes typography, color, density, imagery, shape language, or brand expression.

## Do not load when

- A bounded token or component correction must preserve the established visual direction.
- No rendered interface changes.

## Direction statement

Before major UI work, describe in a short paragraph:

- product character and intended emotional impression;
- typography and color direction;
- layout character and information density;
- shape, border, elevation, imagery, icon, and motion character;
- explicit visual tropes to avoid; and
- why these choices fit this user and task.

Inspect existing brand assets, tokens, screenshots, and repeated components first. Preserve a
coherent working language. If no direction exists, choose one defensible point of view and one
restrained signature detail; do not assemble unrelated trends.

## Make decisions concrete

Prefer statements such as “compact tabular typography and quiet surfaces keep inventory comparison
fast; color is reserved for status” over “modern and clean.” Use hierarchy, spacing, density, type,
shape, and content structure deliberately. Use real product copy and data shapes early because they
change layout decisions.

Do not default to gradient-heavy heroes, translucent cards, universal pills, excessive rounding,
random accent colors, interchangeable SaaS layouts, or large empty introductions. These devices can
be valid only when the product rationale and accessibility constraints support them.

## Evidence

- The direction statement and the existing project evidence it follows or deliberately changes.
- Before/after rendered comparison for a redesign.
- Representative content at narrow and wide viewports.
- A recorded approval when the change replaces the product’s established visual language.
