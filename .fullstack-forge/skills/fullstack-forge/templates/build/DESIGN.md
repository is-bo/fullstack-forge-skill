# Design direction

## Intent

Describe the product's tone, density, and the single reference product or style this should feel
closest to. One paragraph; be specific enough that two different agents would build visually similar
screens from it.

## Non-goals

State what this design deliberately avoids (for example: no dashboard density, no marketing-site
animation, no custom design system). A justified non-goal here prevents scope creep later.

## State coverage baseline

Every screen in this product must define six states unless a reason is recorded here: loading,
empty, error, success, permission-denied, and disabled. Record any screen-level exception with the
reason; do not leave a state undefined by omission.

## Responsive behavior

Describe what changes at narrow, medium, and wide viewports for the product's primary surfaces —
not just that content reflows, but which elements move, collapse, or hide.

Replace each placeholder only with a decision actually made for this project. Do not invent a design
system, component library, or visual language this project has not chosen.
