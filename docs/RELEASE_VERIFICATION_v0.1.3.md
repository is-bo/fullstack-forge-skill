Representative audit of a project containing an aliased SQL injection:

```
findings: 2
  FF-SEC-SQL-001         | FF-SEC-SQL-001:49ebe410ba3836f4         | FAIL
  FF-SEC-VALIDATION-001  | FF-SEC-VALIDATION-001:a68ced6a84e68f33  | FAIL
```

This flow (`const id = req.params.id` then template interpolation into `db.query`) was **not
detected by v0.1.2**, whose detector matched only literal `req.*` text at the sink. Both findings
carry an instance identity.

Fix contract, same clean room:

```
forge security fix --root .          → status: BLOCKED | dry_run: true | changed_files: []
                                       blocked: FF-SEC-SQL-001 (risk=unsupported)
                                       blocked: FF-SEC-VALIDATION-001 (risk=unsupported)
defect status after the refused fix  → FF-SEC-SQL-001 FAIL, FF-SEC-VALIDATION-001 FAIL
```

The refused fix left both defects at `FAIL`. Under v0.1.2 both would have been rewritten to
`BLOCKED`.
