# Audit classification — v0.2.0

Defects reported during the v0.2.0 cycle were reproduced against the integration branch state that
contained them before any fix was written. Classification uses `CONFIRMED`, `PARTIALLY_CONFIRMED`,
`NOT_REPRODUCED`, `INVALID`, and `NOT_VERIFIED`.

This release is scoped to the Build mode milestone. Sources of reported defects: the baseline
specification gap audit against released v0.1.10, and two independent pre-release reviews
(security/evidence-integrity and public-claims/compatibility) of the build-mode implementation.

## Open areas not claimed by this release

- Analyzer depth remains concentrated in a subset of audit modules; the remainder emit inventory
  signals plus `NOT_VERIFIED` (documented in `docs/ANALYZER_SUPPORT.md`).
- Build-mode discipline criteria are conservative by design: without runtime evidence they resolve
  to `NOT_VERIFIED` or a reasoned `NOT_APPLICABLE`, and the independent audit remains the backstop.
- Rendered-UI runtime evidence is not wired into `forge feature check`; UI verification uses the
  audit-side `--url` machinery and honest `NOT_VERIFIED` otherwise.
